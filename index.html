Architecture
Decisions & reasoning
GitOps Pull-based deploy poller instead of a self-hosted GitHub Actions runner

The repo is public; a self-hosted runner on a public repo is a known code-execution risk via fork PRs. A systemd timer polls the repo and applies changes locally instead, so nothing on GitHub's side ever reaches the box directly.

Reliability Resource guardrails on every service, not just the risky ones

Explicit mem/cpu limits across all 21 containers, transcode fencing on the media service, and log rotation, after an early audit showed the box was already touching swap under normal load.

Incident Swap usage quadrupled overnight — investigated, not ignored

Traced with vmstat rather than assumed: confirmed cold-page eviction, not active thrashing, then turned it into a graphed alert condition instead of a manual thing to remember to check.
